# ONI & Co. プロジェクト管理ツール

商品開発とSNS販促計画をガントチャートで管理するツール。
項目はすべてアプリ内で新規作成する（空の状態から始まる）。

データの単位は次の3層:

- **グループ** … ガント縦軸の分類（例: 商品開発 / 販促・イベント）。名前・色を編集でき、追加・削除もできる
- **項目** … ガントのバー1本（商品名・販促名・SNS投稿テーマなど）。いずれかのグループに属す
- **タスク** … 項目にぶら下がる ToDo（例: レシピ確定 / 撮影 / 入稿）。項目の詳細パネル内で管理し、タスク管理ページで横断表示する
- **担当者** … 全体で共有する人のマスタ。ガント項目・タスク・アイデアメモから参照する

## 使い方

**本番はポータル経由**: https://oni-workspace.vercel.app/project/
ポータル（ワークスペース）のアカウントでログインしていればそのまま使える。
このアプリ単体のログイン画面は廃止した（認証はポータルに統合。詳細は `../products/README.md`）。
旧URL https://oni-project-management.vercel.app はポータルへリダイレクトされる。

**デプロイ**: このフォルダを編集したら、ポータル側に同期してデプロイする。

```
cd ../products && ./sync.sh && npx vercel deploy --prod --yes
```

手元で動かして確認したいときは、このフォルダで次を実行し `http://127.0.0.1:8777` を開く。
（Supabase に繋ぐため `file://` のダブルクリックでは動かない。ローカルでは簡易ログインフォームが出る）

```
python3 -m http.server 8777
```

## 画面

| タブ | 内容 |
|---|---|
| **ガント** | メイン画面。年間／四半期／月間／週間で粒度を切り替えられる |
| **タスク管理** | 全項目のタスクを横断して一覧・編集する |
| **アイデアmemo** | 思いつきの書き留め |
| **担当者** | 担当者マスタ。ここに登録した人を各所で選べる |

### ガントチャートの操作

- **ビュー切替** — 年間（年度＝4月始まり）／四半期／月間／週間。どのビューでもバー位置は日単位で正確。表示範囲からはみ出す項目は枠内でクリップ表示（角が平らな側は範囲外へ続いている）
- **タイムラインは連続スクロール** — 横スクロールで時間軸をどこまでも移動できる（端に近づくと自動で範囲が延びる）。‹ › ボタンと ← → キーは1期間ぶんのスライド、**T キー**／「今日」で今日へ
- **「＋ 内容を追加」** — 各グループの一番下にあるボタン。そのグループに項目を追加して詳細が開く
- **空きセルを横にドラッグ** — その期間で新規項目を作成（クリックだけなら1日の項目）
- **バーをドラッグ** — 期間ごと移動（四半期・月間・週間ビュー）
- **バーの左右端をドラッグ** — 開始日・終了日を変更
- **項目名（縦軸）を上下にドラッグ** — 並び替え。別グループの上に落とせばグループ移動
- **項目のチェックボックス** — 複数選択すると下部にバーが出て、まとめて削除できる（ぶら下がるタスクも一緒に消える。確認あり）
- **バーや項目名をクリック** — 詳細パネルが右から開く

描画範囲に重なる項目だけが行として並ぶ。範囲外の件数はツールバーに表示される。

### グループの編集（ガント縦軸）

各グループ見出しにカーソルを合わせると操作ボタンが出る:

- **グリップ（⠿）を上下にドラッグ** — グループごと並び替え
- **色スウォッチ** — クリックで12色パレットから選ぶ（そのグループの項目すべてに反映）
- **✎** — グループ名を変更
- **×** — グループを削除（属する項目とそのタスクも一緒に消える。確認あり）
- 見出し左の三角 — グループを折りたたむ
- 一番下の「＋ グループを追加」で新しいグループを作成

### 季節イベント・出店（ガント上部）

「季節イベント・出店」行で、お盆・祝日・POP-UP などの期間を帯として登録できる。

- ラベル右端の **＋**、または行の空きセルをクリックすると入力フォーム（名前・種類・開始日・終了日）が開く
- 既存のチップをクリックで編集・削除

### タスク管理

ガント項目にぶら下がるタスクを、全項目ぶん横断して表示する。
ここでの編集は各項目の詳細パネル内タスクと即同期する（同じデータ）。
Todoist風の2ペイン構成。

- **左ナビ** — 「INBOX」／「今日」（期限切れ＋今日の件数バッジ）／「近日予定」／「すべて」／「完了済み」のビューに続いて、**項目**リスト（色ドット・未完了件数つき）と**担当者**リスト（アバター・未完了件数つき）。クリックでその項目・その人のタスクだけ表示。担当者セクションには「担当者なし」も出る
- **担当者ビューでのクイック追加**は、その人を担当に自動セットする
- **INBOX** — 期限を決めていないタスクの置き場。空でも常に表示され、新しいタスクの受け皿になる。日付を入れると「今日」「近日予定」へ移る
- **今日** — 期限切れセクション（赤）＋今日が期限のタスク
- **近日予定** — 期限切れ／今日／明日／今後1週間の日付ごと／それ以降
- **すべて** — 項目ごとのセクション（見出しクリックで項目の詳細へ）＋未割り当て
- **タスク行** — 丸チェックで完了、タイトルはインライン編集。期限チップ（期限切れ=赤・今日=緑・明日=橙。クリックでカレンダー、×で解除）、項目チップ（クリックで割り当て変更）、担当
- **クイック追加** — 各セクション末尾の「＋ タスクを追加」。日付セクションならその日が期限に、項目セクションならその項目に自動で紐付く。Enterで連続追加、Escで閉じる
- 完了したタスクは各ビューから消え、「完了済み」ビューに残る（チェックを外せば復活）
- **空を隠す** — 左ナビ「項目」見出しの右のボタン。タスクが1件も割り当てられていない項目と、担当タスクが0件の担当者をナビから隠す（「すべて」ビューの空セクションも同時に隠れる）。表示中のものは隠れない。INBOX と上部の4ビューは常に表示

### 担当者マスタ

「担当者」タブで、全体で共有する人の一覧を管理する。

- 名前を入れて「＋ 追加」で登録。色は12色パレットから選べ、頭文字のアバターに反映される
- **グリップ（⠿）を上下にドラッグ**して並び替え（この順番が各所のピッカーやタスクのサイドバーにも反映される）
- メモ欄に役割などを書ける
- 各行に「項目 n ・ タスク n ・ メモ n」と割り当て件数が出る
- 削除すると、割り当て済みの箇所は「担当者なし」に戻る（件数を示して確認）

登録した担当者は次の3か所で選べる（いずれも同じチップ型のピッカー）。

| 場所 | 項目 |
|---|---|
| ガント項目の詳細 | テキスト担当 / ビジュアル担当 |
| タスク | 担当（タスク管理ページ・詳細パネル内チェックリストの両方） |
| アイデアmemo | 記載者 |

**複数人を割り当てられる。** チップを押すと担当者一覧が開き、名前をクリックするたびに選択が切り替わる（ポップオーバーは開いたままなので続けて選べる）。「全員を外す」で一括解除。
チップにはアバターが重なって並び、3人以上は「ながせ 他2人」と表示される。

検索は担当者名でも引っかかる（ガントの項目検索・タスク検索の両方）。

### 詳細パネル

グループ／期間／ステータス／優先度／配信媒体／担当と、
自由記述の企画メモ・参考URLを編集できる。入力は自動保存。`Esc` で閉じる。
**タスクのチェックリスト**もここに組み込まれており、その場で追加・完了・担当・期限を設定できる。複製もここから。

### プロパティの編集（Notion風）

**プロパティ名をクリックすると設定エディタが開く。** 組み込み・自作の区別なく編集できる。
**行の左端のグリップ（⠿）を上下にドラッグすると並び順を変更できる**（組み込みと自作を混ぜて自由に並べられる）。

追加は「＋ プロパティを追加」から。型は
**選択 / マルチセレクト / テキスト / 数字 / 期間 / ステータス / URL** の7種。

| | 組み込み（グループ・期間・ステータス・優先度・配信媒体・担当） | 自作プロパティ |
|---|---|---|
| 名前の変更 | ○ | ○ |
| 型の変更 | ×（機能に紐付くため固定） | ○ |
| 値の編集 | ○ | ○ |
| 選択肢の編集 | ○（ステータス・優先度・配信媒体） | ○（選択系のみ） |
| 非表示 | ○ | — |
| 削除 | ×（非表示で代用） | ○ |
| 並び替え | ○ | ○ |

- 定義は全項目で共通（追加すると全項目に現れる）
- **バーの色** — 項目ごとにガントバーの色を12色パレットから選べる。未設定ならグループの色を継承し、「グループの色に戻す」でいつでも戻せる

### カラーパレット（12色）

グループの色も項目のバー色も、共通の12色から選ぶ。
ブランド指針に沿って暖色・低彩度でまとめ、青紫系は含めない。

鬼赤 `#8C1D23` / 弁柄 `#A8443C` / 照柿 `#C2703A` / 山吹 `#D69A4C` /
芥子 `#A8894B` / 鶯茶 `#7E7A3C` / 苔緑 `#6B7A5A` / 深緑 `#4F6B57` /
焦茶 `#6E5A46` / 胡桃 `#8A6D5D` / 桜鼠 `#B4818A` / 墨灰 `#5A5550`

定義は `js/model.js` の `COLOR_PALETTE`、UI部品は `js/ui.js` にある。
- 配信媒体は**略称**も編集でき、ガントのバー上の表示に反映される
- 優先度の選択肢名を変えると、既存項目の値も自動で移し替わる
- 選択肢を削除すると、その値を持つ項目からは値が外れる（ステータスは先頭の選択肢へ寄る）
- ステータス・配信媒体の編集は、絞り込みメニューの選択肢にも即反映される
- 選択系は値の横の「＋」でも選択肢をその場で追加できる

## データと共有

データは **Supabase**（プロジェクト `abweoowonthzpuoselix`）に保存され、メンバー全員で共有される。
Realtime を有効にしてあるので、他の人の変更はリロードなしで画面に反映される。

画面側は今までどおり同期的に動く。`js/store.js` がメモリ上のキャッシュを持ち、
「先に画面を更新 → 裏で Supabase に書き込み → Realtime で他の人の変更を取り込む」
という流れで橋渡ししている。

初回起動時は既定グループ（商品開発 / 販促・イベント / SNS投稿 / 撮影・素材準備）だけが入っており、
名前・色の変更や追加・削除は自由。

### テーブル

既存の社内システム（レシピ・アレルゲン・商談など）と混ざらないよう `pm_` を付けている。

| テーブル | 内容 |
|---|---|
| `pm_workspace_users` | ログインできる人とロール（admin / editor / viewer） |
| `pm_members` | 担当者マスタ |
| `pm_groups` | ガント縦軸のグループ |
| `pm_items` | ガントのバー（`detail` は jsonb） |
| `pm_tasks` | タスク（`owner` は担当者IDの配列） |
| `pm_events` | 季節イベント・出店 |
| `pm_ideas` | アイデアmemo |
| `pm_prop_defs` | カスタムプロパティ定義 |
| `pm_settings` | 組み込みプロパティの設定（1行） |

## ログインとメンバー管理

パスワードは扱わず、**メールに届くリンク**でログインする（マジックリンク）。

- **@oni-co.jp のアカウント**は初回ログイン時に自動でワークスペースに参加する
- それ以外のドメインは、管理者が `pm_workspace_users` にメールを登録した場合のみ参加できる
- 登録されていない人は、ログインできてもデータは一切見えない（「アクセス権限がありません」と表示）

権限は3段階。RLS（行レベルセキュリティ）でデータベース側から強制している。

| ロール | できること |
|---|---|
| `admin` | 全データの読み書き＋メンバーの追加・権限変更・削除 |
| `editor` | 全データの読み書き |
| `viewer` | 閲覧のみ |

`js/supabase-config.js` に置いてある publishable key は**ブラウザに公開して良い種類のキー**で、
データを守っているのは RLS のほう。未ログイン状態では読み取り0件・書き込み拒否になることを確認済み。

## デプロイ（Vercel）

ビルド不要の静的サイトなので、リポジトリをそのまま Vercel に繋げばよい。
`vercel.json` と `.vercelignore` は用意済み（社内の xlsx は公開対象から除外している）。

初回だけ次の手順が必要（GitHub と Vercel の認証はご自身の操作が要る）。

```bash
# 1. GitHub に空のプライベートリポジトリを作る（例: oni-project-management）

# 2. このフォルダから push する
cd "~/Documents/Claude/project management"
git remote add origin https://github.com/<ユーザー名>/oni-project-management.git
git branch -M main
git push -u origin main
```

3. [vercel.com/new](https://vercel.com/new) でそのリポジトリを Import する
   - Framework Preset: **Other**（ビルドコマンドなし）
   - Root Directory: そのまま
4. Deploy を押すと URL が発行される

5. 発行された URL を Supabase に登録する（メールのリンクから戻れるようにするため）
   - Supabase ダッシュボード → Authentication → URL Configuration
   - **Site URL** に本番URL、**Redirect URLs** に本番URLを追加

以降は `git push` するたびに自動でデプロイされる。

## ファイル構成

```
index.html               画面の骨組み
vercel.json              デプロイ設定（セキュリティヘッダなど）
css/app.css              ブランドカラー・レイアウト
js/supabase-config.js    接続先とキー
js/auth.js               ログイン画面とセッション管理
js/model.js              スキーマ定義、日付ユーティリティ、祝日表、12色パレット
js/ui.js                 共通UI部品（カラーピッカー・担当者ピッカー）
js/store.js              データの保存・取得（Supabase との同期はここに集約）
js/gantt.js              タイムライン描画とドラッグ操作
js/detail.js             詳細パネル
js/app.js                状態管理とイベント配線
```

ビルドツールを使わないため、ES modules ではなく classic script と
グローバル名前空間 `ONI.*` で分割している。

起動の流れは `auth.start()` → `store.setClient()` → `store.init()` → `app.init()`。

## 祝日データ

`js/model.js` の `HOLIDAYS` に 2026年7月〜2027年6月分を定義している。
年度が変わったら追記すること。
```
